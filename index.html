Enhancement One: Software Design and Engineering

Original artifact: View Original Animal Shelter Dashboard on GitHub

Enhanced artifact: View Enhancement One Files

Narrative: I selected this artifact for this enhancement, because, while it functions as it was intended, it was built as a brief introduction into Jupyter Notebook. While this is one method of coding in Python, it was not structured in such a way as to easily be expanded or enhanced. Using this artifact will demonstrate my ability to take an existing project and improve areas that could make the application easier to maintain, understand, and expand. During the enhancement process, I focused on improving the organization of the application by separating the user interface, callbacks, and application logic into separate, more manageable components. I also created a login page that will, in the upcoming enhancements, allow different access levels for administrators and regular users. These changes helped me better understand the importance of separating responsibilities within an application and designing features around the needs of different users.

I believe the enhancements addressed the course outcomes I originally identified in Module One. The improvements to the application structure and user experience support Outcome One by making the application more organized and useful for its intended audience. The dashboard's visual components, along with the documentation and presentation of the project, support Outcome Two. The filtering and database retrieval functionality demonstrate Outcome Three by applying programming and data-processing techniques to solve a practical problem. The use of Python, Dash, and MongoDB, along with improvements to the application's organization, supports Outcome Four by demonstrating the ability to work with industry-relevant development tools. Finally, the addition of administrator and regular-user access levels will support Outcome Five by demonstrating an awareness of access restrictions and the importance of protecting application functionality. I do not believe my original outcome-coverage plan needs major changes because the enhancements continued to address the same areas of development I identified at the beginning of the course.

One of the most valuable parts of this process was returning to a project I had completed previously and examining it from a software engineering perspective rather than simply looking at whether it worked. I learned that an application can function correctly, but still have opportunities for improvement in organization, maintainability, security, and usability. Separating application responsibilities has helped me better understand how different parts of a program interact and how changes in one area can affect other components. One challenge was making structural improvements without disrupting existing functionality. I wanted to preserve the original dashboard features while introducing changes, which required careful testing and troubleshooting. I also encountered challenges with application configuration. Because this artifact was originally written over a year ago, many of the dependencies needed were either outdated or completely obsolete. In some instances the PyCharm IDE I am using would ask if I wanted to install the correct updated version. In others, I needed to go to the Jupyter website to research what corrections I needed to make for the application to resume functioning. Overall, this experience has improved my understanding of software development as an ongoing process. I have learned that creating a successful application involves more than just writing code that works. It also requires considering future maintenance, security, user needs, and the ability to expand the application as requirements change.
