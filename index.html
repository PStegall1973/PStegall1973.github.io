Enhancement One: Software Design and Engineering

Original artifact: View Original Animal Shelter Dashboard on GitHub

Enhanced artifact: View Enhancement One Files

Narrative: I selected this artifact for this enhancement, because, while it functions as it was intended, it was built as a brief introduction into Jupyter Notebook. Using this artifact will demonstrate my ability to take an existing project and improve areas that could make the application easier to maintain, understand, and expand. During the enhancement process, I focused on improving the organization of the application by separating the user interface, callbacks, and application logic into separate, more manageable components. I also created a login page that will, in the upcoming enhancements, allow different access levels for administrators and regular users. These changes helped me better understand the importance of separating responsibilities within an application and designing features around the needs of different users.

I believe the enhancements addressed the course outcomes I originally identified in Module One. The dashboard's visual components, along with the documentation and presentation of the project, support Outcome Two. Finally, the addition of administrator and regular-user access levels will support Outcome Five by demonstrating an awareness of access restrictions and the importance of protecting application functionality. I do not believe my original outcome-coverage plan needs major changes because the enhancements continued to address the same areas of development I identified at the beginning of the course.

One of the most valuable parts of this process was returning to a project I had completed previously and examining it from a software engineering perspective rather than simply looking at whether it worked. I learned that an application can function correctly, but still have opportunities for improvement in organization, maintainability, security, and usability. Separating application responsibilities has helped me better understand how different parts of a program interact and how changes in one area can affect other components. Overall, this experience has improved my understanding of software development as an ongoing process. I have learned that creating a successful application involves more than just writing code that works. It also requires considering future maintenance, security, user needs, and the ability to expand the application as requirements change.

Enhancement Two: Algorithms and Data Structures

Original artifact: View Original Animal Shelter Dashboard on GitHub

Enhanced artifact: View Enhancement Two Files

Narrative: I selected this artifact for this enhancement because the original application provided an opportunity to improve on how animal records were retrieved and processed. The dashboard originally used three separate MongoDB queries to retrieve records for Water, Mountain, and Disaster rescue categories. Each query returned a separate set of records that was converted into a Pandas DataFrame. For the “All Rescues” option, the results were then combined using concatenation, followed by duplicate removal. Although this approach worked, it involved multiple database requests and additional processing in Python. I wanted to determine whether the same results could be produced more efficiently. I revised the logic by combining the three rescue filters into a single MongoDB query using an $or condition. This allowed MongoDB to retrieve the matching records in one request rather than requiring three separate queries. The revised approach also eliminated the need to concatenate multiple DataFrames and remove duplicate records.

I believe this enhancement addressed the course outcomes I originally identified in Module One. The dashboard's filtering and data retrieval functionality supports Outcome Three by demonstrating the application of algorithmic principles and data-processing techniques to solve a practical problem. I evaluated the original and revised approaches by measuring their execution times and verifying that they returned the same animal records. Using Python's time.perf_counter(), I conducted 20 measured comparisons, alternating the execution order of the two approaches. Both approaches returned the same 42 animal records, confirming that the revised query preserved the original results. However, the original approach had a median execution time of 170.455 milliseconds, compared with 64.368 milliseconds for the revised approach. This represented a 62.24% reduction in median execution time. The enhancement also supports Outcome Four by demonstrating the use of Python, Pandas, and MongoDB to evaluate and improve a computing solution using industry-relevant tools. Outcome Two is supported through the documentation and presentation of the testing process and results. The dashboard's ability to organize and present animal information also supports Outcome One by providing useful information to its intended audience. Finally, Outcome Five is supported by considering the reliability and integrity of the returned records and verifying that the optimization did not change the original results. I do not believe my original outcome-coverage plan needs major changes because this enhancement continued to address the areas I identified at the beginning of the course.

One of the most valuable parts of this process was learning to evaluate an algorithm based on its actual performance rather than assuming that a different approach would automatically be better. I initially examined how the dashboard retrieved records and identified that the original implementation made three separate database requests. Combining the queries seemed like a reasonable improvement, but I wanted to verify that it actually made a difference. Testing the two approaches helped me understand the importance of measuring execution time and checking the accuracy of the results. One challenge was making sure that the revised query returned exactly the same records as the original implementation. Comparing only the number of records would not have been enough, so I added a record-by-record comparison to the test The terminal view in PyCharm showed that MongoDB examined all 10,000 documents for both the individual rescue queries and the combined query. This helped me understand that the performance improvement came from reducing database requests and Python-side processing rather than reducing the number of documents scanned by MongoDB. Overall, this enhancement improved my understanding of algorithms and data structures by showing me how query design, database operations, and data processing affect application performance. I learned that an effective solution must not only produce correct results but should also use resources efficiently and be supported by measurable testing.
